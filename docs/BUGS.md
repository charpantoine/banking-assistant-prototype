# Bugs found so far

One line per bug. Read this before changing agents.py: most fixes are rules enforced in code, and the regression test names the behaviour that must not come back.

| # | Symptom | Root cause | Fix | Regression test |
|---|---------|------------|-----|-----------------|
| 1 | "Lock my debit card" got "which card?" although the card was named (stage 4) | Action prompt rule on several cards was too strong | Prompt: a type or last 4 digits matching exactly one card is proposed at once | test_04_lock_card_only_after_confirm |
| 2 | French messages mixed languages ("Votre Debit card ****4821 est bloquée") | Card label built from the English mock data | _card_in translates the card type with CARD_TYPES for French messages | test_french_confirmation_translates_card_label |
| 3 | "How do I lock my card if I lose it?" routed to action and proposed a lock | Router prompt did not separate "how to" questions from requests to act | how-to and hypothetical questions -> faq, two contrasting examples in the prompt; FAQ adds the "I can lock a card now" offer | test_router (2 cases), test_how_to_lock_question_gets_faq_answer_with_offer |
| 4 | No feedback while the agent worked; a second message could be sent meanwhile | Single event: nothing shown until handle_turn returned | Two chained steps (question and "…" at once, then the turn) and inputs disabled until a third step re-enables them | test_show_question_returns_placeholder_and_disables_buttons |
| 5 | Dark mode followed the OS; banner hard to read | Gradio follows the OS theme; banner had no explicit text colour | Reload with ?__theme=light; banner text forced dark grey | test_light_mode_forced_and_banner_readable |
| 6 | Turns felt slow | Router waited for the input guardrails; output moderation also ran on code-written templates | Router in parallel with the guardrails (route discarded if flagged); moderation skipped for FixedText | test_06_other_customer_refused_without_any_call, test_07_out_of_scope_refusal, test_01_faq_answer_cites_source |
| 7 | Confirm/Cancel result merged into the proposal bubble | Chatbot groups consecutive messages of the same role by default | group_consecutive_messages=False | test_chatbot_keeps_consecutive_messages_separate |
| 8 | "merci" / "thanks" went through the router and agents | No small-talk handling | COURTESY_WORDS answered in code with a fixed template, no router | test_merci_after_handoff_gets_french_courtesy_without_new_handoff |
| 9 | A second handoff request produced a new summary each time | No memory of the handoff in the session | session["handoff_done"]; later handoffs get "already notified" | test_second_handoff_request_says_already_notified |
| 10 | Short messages ("dis quoi") switched a French conversation to English | detect_lang defaulted to English on a tie | Ties on messages under 3 words return "unknown"; the session language is kept | test_short_unclear_message_keeps_french, test_detect_lang |
| 11 | Router repeated the previous route instead of reading the new message | Prompt let earlier messages weigh on the route | Prompt: the latest user message decides; history is context only | test_help_after_refusal_routes_to_help_in_french |
| 12 | "for example?" after a refusal had no useful answer | No route for questions about the assistant | help route with a fixed template; out_of_scope ends with examples | test_help_after_refusal_routes_to_help_in_french, test_07_out_of_scope_refusal, test_visitor_help_lists_visitor_capabilities_only |
| 13 | After switching to visitor, earlier balances stayed in the chat and history | Mode switch only flipped a flag on the same session | Any mode switch starts a new session (audited with both ids) | test_no_balance_left_after_switching_to_visitor, test_switching_to_visitor_starts_new_session |
| 14 | Handoff summary called a visitor a "logged-in customer" | Status hard-coded in the handoff prompt | {status} filled from the session | test_handoff_prompt_names_customer_status |
| 15 | "lock my card" with 2 active cards proposed the debit card without asking | Card choice left to the model | Code accepts a card only if the latest message names exactly one active card, else "which card?" | test_lock_my_card_with_two_active_cards_asks_which, test_propose_rejects_card_not_named_in_message |
| 16 | After "not that card", the earlier proposal could still be confirmed | Pending action stayed while the user typed | Any message other than a confirmation word clears it; follow-up handled in code | test_not_that_card_clears_debit_proposal, test_credit_then_actually_debit_proposes_debit_only, test_new_message_clears_pending_and_hides_card |
| 17 | "lock Debit card ****7232" proposed Debit card ****4821 | _named_cards matched on type OR digits | All identifiers must agree; unknown digits get "I can't find a card ending ..." | test_type_with_wrong_digits_gives_no_pending_action, test_propose_lock_card_identifiers_must_agree |
